# CodeVault

CodeVault is a Python-based automation tool that backs up accepted LeetCode submissions to GitHub, organizes them by date, and keeps a local state so it only fetches new solutions after each run.

It is designed for people who want a simple backup workflow for daily coding practice, especially when running it automatically via GitHub Actions.

## Features

- Automatically fetches accepted LeetCode submissions
- Saves solutions in a date-based folder structure
- Avoids duplicate processing using `state.json`
- Commits and pushes backups to GitHub
- Retries failed pushes and preserves pending work in a queue
- Sends email notifications for failures, downtime, and other issues
- Supports multiple languages through the file extension map

## Project purpose

This project is useful if you want to:

- keep a backup of your accepted coding solutions in GitHub
- review your progress over time
- store code in a structured daily archive
- run the backup automatically on a schedule without manual effort

## Tech stack

CodeVault is built with a simple Python-based automation stack:

- Python 3.10+
- GitHub Actions for scheduled automation
- Git for commit and push workflow
- LeetCode web session/cookie-based fetching
- Gmail SMTP for email notifications
- YAML-based configuration via `config.yaml`
- GitHub PAT authentication for repository write access

This keeps the project lightweight, portable, and easy to run locally or in CI.

## Requirements

Before using the project, make sure you have:

- Python 3.10+
- Git
- A LeetCode account
- A GitHub repository where backups will be pushed
- A Gmail account if you want email notifications

## Step 1: Clone the repository

```bash
git clone https://github.com/uddesh-1707/codevault.git
cd codevault
```

### Clean generated owner backup data after cloning

If you are cloning this repo for personal use and do not want the previous owner's backup files or checkpoint data, remove them immediately after cloning:

```bash
rm -rf backup
rm -f state.json
rm -f backup.log
```

This removes:

- the existing backup archive from the original owner
- the saved checkpoint file used to track the last backup
- the log file generated by previous runs

If you want a completely fresh start, run:

```bash
rm -rf backup
rm -f state.json
rm -f backup.log
python src/main.py
```

## Step 2: Create environment variables

Copy the template file and fill in your credentials:

```bash
cp .env.template .env
```

Then edit `.env` and replace the placeholder values:

```env
LEETCODE_SESSION=your_leetcode_session_cookie_here
LEETCODE_CSRF_TOKEN=your_csrftoken_here
PAT_TOKEN=your_github_personal_access_token_here
EMAIL_SENDER=your_email@gmail.com
EMAIL_PASSWORD=your_16_char_gmail_app_password
EMAIL_RECIPIENT=your_email@gmail.com
SMTP_SERVER=smtp.gmail.com
SMTP_PORT=587
```

### Important notes

- `LEETCODE_SESSION` and `LEETCODE_CSRF_TOKEN` come from your LeetCode session cookies.
- `PAT_TOKEN` must have permission to push to your GitHub repo.
- `EMAIL_PASSWORD` should be a Gmail app password, not your normal Gmail password.
- Never commit `.env` to Git. It is already ignored in `.gitignore`.

## Step 3: Configure the project

Edit `config.yaml` and set your LeetCode username:

```yaml
platforms:
  leetcode:
    enabled: true
    username: "your_leetcode_username"

backup:
  root_dir: "backup"
  file_extension_map:
    cpp: ".cpp"
    python: ".py"
    java: ".java"
    javascript: ".js"
    typescript: ".ts"
    default: ".txt"

logging:
  level: "INFO"
  file: "backup.log"

git:
  commit_message: "Auto backup: {date}"
  max_retries: 3
  retry_delay_seconds: 5

notifications:
  enabled: true
```

## Step 4: Install dependencies

```bash
pip install -r requirements.txt
```

If you want to install the package locally as well:

```bash
pip install -e .
```

## Step 5: Run the backup locally

```bash
python src/main.py
```

This will:

- validate your LeetCode credentials
- fetch recent accepted submissions
- save new files under `backup/YYYY-MM-DD/`
- update `state.json`
- try to commit and push changes to GitHub

## GitHub Actions setup

This project includes an automated workflow in `.github/workflows/leetcode_backup.yml`.

### Required GitHub repository secrets

Add these in GitHub:

- `LEETCODE_SESSION`
- `LEETCODE_CSRF_TOKEN`
- `PAT_TOKEN`
- `EMAIL_SENDER`
- `EMAIL_PASSWORD`
- `EMAIL_RECIPIENT`

The workflow runs automatically every 6 hours by cron schedule, and it can also be triggered manually from the Actions tab.

### Important GitHub permission note

If the push fails with a `403` permission error, the token is usually the problem. Make sure the PAT belongs to an account that has write access to the repository and that the PAT includes repository write permissions.

## Backup output format

The tool stores files like this:

```text
backup/
├── 2026-08-05/
│   ├── Roman_to_Integer.cpp
│   └── Two_Sum.py
├── 2026-08-06/

```

The exact file names are generated from the LeetCode problem title and chosen extension.

## State and queue behavior

The project keeps a local tracking file named `state.json` so it only processes new submissions after the last successful backup.

If a GitHub push fails, the project will:

- save the commit to a local queue
- keep it local until the next run
- avoid advancing the saved checkpoint until the push succeeds

This is intentional and helps prevent duplicate processing during short GitHub outages.

## Troubleshooting

### Git push fails with 403

This usually means the GitHub PAT is invalid, expired, or lacks permission. Check:

- the repository is correct
- the token has `repo` or repository write access
- the secret in GitHub Actions is valid

### LeetCode credentials fail

- verify that the session cookie is fresh
- refresh the CSRF token
- make sure you are logged in to LeetCode in the same browser session used to fetch cookies

### Email notifications fail

- use a Gmail app password, not your regular password
- verify the sender and recipient emails
- confirm SMTP settings are correct

### Local run is repeating same submissions

Delete `state.json` and run again if you want to reset the checkpoint:

```bash
rm -f state.json
python src/main.py
```

## Reset and clean local generated files

If you want to start fresh and remove generated backup data, state tracking, and logs, run:

```bash
rm -rf backup
rm -f state.json backup.log
```

This removes:

- the generated backup folder
- the local checkpoint file tracking the last backup
- the log file created during execution

If you want to reset everything and rerun the tool from scratch, use:

```bash
rm -rf backup
rm -f state.json backup.log
python src/main.py
```

## Git status cleanup

After deleting generated files, you can check what remains:

```bash
git status --short
```

If you want to clean the git working tree of generated content entirely before a new run, you can also do:

```bash
git restore --staged .
git restore .
```
